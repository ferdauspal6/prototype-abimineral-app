Alur penjualan sampai penagihan

Flowchart ini mengikuti perilaku aplikasi yang berjalan saat ini: order dibuat oleh Sales, dikonfirmasi Admin, dikirim lewat surat jalan, dibayar, lalu sisa tagihan masuk ke piutang dan penagihan. Setiap aksi juga menuliskan efek datanya, sehingga cocok dipakai sebagai panduan demo ke client.

Catatan: Sales hanya melihat pelanggan dan menu miliknya. Admin memiliki akses penuh. Manager melihat operasional tanpa menu pengguna/role.
1. Alur utama end-to-end
Jalur normal dari order baru sampai lunas
geser untuk melihat seluruh alur
Sales

Pilih pelanggan

Menu Order → pelanggan sesuai jadwal kunjungan (hari & pekan) atau tab Semua.

Sales

Buat order

Input qty, promo otomatis, metode bayar, diskon khusus (Admin), PPN 11%.

Sistem

Order tersimpan

Status Belum Diproses (pending), kode INV, stok langsung berkurang, jatuh tempo +14 hari (Tunai: hari ini).

Admin

Konfirmasi order

Status berubah menjadi Siap Dikirim (already), satuan atau massal.

Admin

Buat surat jalan

Pilih order, periode, driver, armada, gudang. Order menjadi Dikirim (shipping).

Admin / Gudang

Konfirmasi surat jalan

Input pembayaran tunai/transfer per order saat barang sampai. Surat jalan selesai.

Sistem

Order Selesai. Pembayaran tercatat. Sisa tagihan otomatis menjadi piutang.

Admin / Keuangan

Penagihan

Buat surat jalan penagihan → input pembayaran → piutang berkurang sampai lunas.

Sistem

Dashboard & laporan

2. Detail tiap tahap
Aksi, status, dan efek data yang benar-benar terjadi
0
Admin Persiapan master data
  • • Kelola pelanggan (jadwal kunjungan, channel, jenis harga, sales penanggung jawab).
  • • Kelola promo (potongan harga / bonus barang + periode berlaku).
  • • Kelola barang & gudang, lalu isi stok awal melalui Stock.
  • • Kelola jenis pendapatan/pengeluaran dan pengguna/role.
Efek data: mengisi customers, products, promos, warehouses, users, dan roles.
1
Sales Pilih pelanggan sesuai jadwal
  • • Menu Order → tab Jadwal memfilter pelanggan berdasarkan hari dari tanggal kunjungan.
  • • Tab Semua menampilkan seluruh pelanggan milik Sales tersebut.
  • • Tombol Order membuka kamera (simulasi) → konfirmasi foto → masuk ke form order.
Efek data: belum ada data berubah; hanya memilih selectedCustomerId.
2
Sales Buat order
  • • Pilih produk & qty; harga mengikuti jenis harga pelanggan (dalam/luar kota).
  • • Promo aktif terhitung otomatis: diskon persen atau bonus barang (kelipatan bila diaktifkan).
  • • Pilih metode pembayaran (Tunai / Kredit / Transfer). Diskon khusus hanya untuk Admin.
  • • PPN 11% dihitung dari subtotal setelah diskon. Stok dicek sebelum preview.
Efek data: orders +1 dengan status pending; products.stock dikurangi; customers.lastOrder diperbarui; kode INV/YYYY/MM/xxxx; jatuh tempo +14 hari (Tunai: hari ini).
Belum Diproses → Siap Dikirim
3
Admin Konfirmasi order
  • • Buka Order → tombol centang pada baris, atau pilih beberapa order lalu Konfirmasi massal.
  • • Order pending berubah ke already (Siap Dikirim).
  • • Order yang belum dikonfirmasi masih bisa dihapus; stok dikembalikan.
Efek data: orders.status menjadi already; due date dipastikan terisi.
4
Admin Gudang / Driver Surat jalan & pengiriman
  • • Menu Surat Jalan → Buat: pilih order berstatus Siap Dikirim / Ditahan / Parsial.
  • • Lengkapi periode, driver, armada, dan gudang asal, lalu preview dan submit.
  • • Order di dalam surat jalan berubah menjadi shipping (Dikirim).
  • • Order bisa dikeluarkan dari surat jalan bila perlu; statusnya kembali already.
Efek data: deliveries +1 status pending; orders.status = shipping.
5
Admin Driver / Gudang Sistem Konfirmasi surat jalan & pembayaran
  • • Buka detail surat jalan → Konfirmasi. Input nominal tunai dan transfer per order.
  • • Nominal dibatasi maksimal sebesar nilai order; sisa dihitung otomatis.
  • • Bila lunas → pembayaran paid. Bila ada sisa → partial dan piutang dibuat.
  • • Surat jalan berubah ke success, order berubah ke success.
Efek data: payments +1 per pembayaran; receivables dibuat/diupdate (cash, transfer, unpaid); status order & delivery menjadi success.
6
Admin / Keuangan Piutang & penagihan
  • • Menu Piutang menampilkan tagihan dengan sisa > 0 (tab Aktif).
  • • Buat Penagihan: pilih sales, tanggal, dan piutang yang akan ditagih.
  • • Konfirmasi Penagihan: input tunai/transfer per piutang, maksimal sebesar sisa.
  • • Bila belum lunas → collection processing; bila lunas → success dan pindah ke tab Lunas.
  • • Bukti pembayaran dapat dicatat dari halaman piutang.
Efek data: collections +1; receivables.cash/transfer/unpaid diperbarui; payments +1 per pembayaran.
7
Admin Sistem Return, stok, dan laporan
  • • Return dibuat dari order → pilih barang, qty, jenis (Ganti Barang / Potong Harga), kondisi, keterangan.
  • • Proses return: Potong Harga mengurangi nilai piutang dan menambah stok; Ganti Barang tidak menambah stok.
  • • Stock: tambah stok dan opname (+/-) langsung mengubah stok produk.
  • • Dashboard, grafik, dan laporan CSV dihitung ulang dari data aktual.
Efek data: returns, products.stock, stockHistory, opnames, receivables, serta KPI dashboard.
3. Percabangan & keputusan
Kondisi yang mengubah jalur normal
Stok cukup?
Cek stok saat preview → Ya → order disubmit
Tidak → submit diblokir → Tampilkan toast error

Order baru langsung mengurangi stok. Menghapus order yang belum dibayar mengembalikan stok.

Pembayaran saat surat jalan
Tunai + transfer → Sisa 0 → Lunas
Sisa > 0 → Partial → Piutang aktif → Penagihan

Pembayaran penuh menutup order. Sisa tagihan tetap terlihat di menu Piutang dan ikut KPI.

Jenis return
Potong Harga → Stok + qty → Piutang − nilai return
Ganti Barang → Discard → Stok tetap

Return berstatus pending sampai di-proses. Return yang sudah diproses tidak bisa diproses ulang.

Order batal / ditahan
Hapus order → Hanya pending / already → Stok kembali
Sudah ada pembayaran → Tidak bisa dihapus

Status holding (Ditahan) tersedia pada data demo dan tetap bisa dimasukkan ke surat jalan.

7. Skenario demo yang disarankan
Urutan singkat saat presentasi
  1. Login sebagai Sales → buat order untuk pelanggan hari ini → submit.
  2. Refresh halaman → tunjukkan order tetap ada dan stok sudah berkurang.
  3. Ganti role ke Admin → konfirmasi order → buat surat jalan.
  4. Konfirmasi surat jalan dengan pembayaran sebagian → tunjukkan piutang terbentuk.
  5. Buat penagihan → bayar sisa → piutang pindah ke tab Lunas.
  6. Proses return → tunjukkan stok/piutang berubah.
  7. Kembali ke dashboard → angka KPI, grafik, dan status ikut berubah.
  8. Buka Pengaturan → Data Demo → Export JSON sebagai backup state.
8. Catatan implementasi prototype
Agar ekspektasi demo jelas
Penyimpanan: seluruh data disimpan di localStorage browser dengan kunci abi-mineral-demo. Tidak ada server/API.
Tanggal & nomor dokumen: dibuat relatif terhadap hari ini agar demo selalu terlihat baru.
Kontrol data: Export JSON, Import JSON, Hapus Transaksi, dan Reset Data tersedia di menu user serta Pengaturan → Data Demo. Hapus Transaksi mengosongkan seluruh transaksi tanpa menghapus master data.
Batasan: data terikat pada browser/perangkat; upload bukti pembayaran hanya menyimpan nama file; password demo disimpan sebagai teks biasa.
Sinkronisasi: perubahan di satu tab otomatis diterapkan ke tab lain pada browser yang sama.
